# KB-02 · Symptom, likely cause, what to do

| Symptom on the floor | Likely cause | How to confirm | What to do |
|---|---|---|---|
| Robots jump at the same place every time | A piece of the map is misplaced; the place is the seam | **Detect with Recording** shows `JUMP`; **Find rigid pieces** shows two long pieces with a step between | [[WI-02]], [[WI-03]] |
| After a fix, the jump is gone there but appears somewhere else | Only part of the misplaced piece was moved, so the seam moved | Replay the new map: a step at the edge of what was moved | Move the whole piece: [[WI-03]], and read [[KB-03]] |
| A rescan of the area did not help | The rescan was joined onto the misplaced piece and inherited its error | Replay the rescanned map: same step, maybe shifted | [[WI-02]] on the rescanned map |
| Robot stops with a virtual-laser fault at one spot on a path | A feature line lies on or beside the path | **Detect** marks `line on path` | [[WI-06]], [[KB-06]] |
| Low confidence through one area, position stays right | Movable things (bins, pallets, racks) are not in the map, or were scanned in and have moved | Replay: red laser dots where the map has no walls, or walls where there are no laser dots | Usually nothing. If walls are wrong, **Take walls** from a better map ([[WI-06]]) |
| One robot misbehaves where the others are fine | That robot has a different map, or its own fault | **Check maps on all robots** | [[WI-07]] |
| Robot docks a few centimetres off at one station | The station is slightly off in the map | Measure on the floor | Move that station by hand ([[WI-06]]) |
| Robot drives backward where it should drive forward | The path's direction property | **Select** the path in the Edit tab | [[WI-06]] |
| An edit made on the robot has disappeared | A file that did not contain it was loaded over it | Download the robot's map and **Compare** with the file you expect | Rebuild from the robot's current file ([[WI-05]], last section) |
| Map looks right, robot still loses position after standing or being pushed | Not a map fault: the robot was moved without knowing | Recording summary shows the position restart | Relocalise; no map change |

## Which questions the tools cannot answer

- Whether a robot's scanner, wheels or parameters are at fault. If every map test passes and one robot still misbehaves, look at the robot.
- Whether a dock position is right to the millimetre. That needs a look at the robot in the dock.
- Anything about places no recording has driven through.
