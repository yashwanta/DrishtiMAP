# KB-07 · Rules and limits of this program

## Rules built in

- **Read-only on robots.** The only requests the program can send are: robot information (1000), position (1004), laser scan (1009), list of maps (1300) and download a map (4011). No part of the program can load a map, change a parameter, relocalise or move a robot. Settings shows the list.
- **Read-only on plant servers.** For a past event ([[WI-09]]) the program reads the fleet manager's history through your own SSH login, with one built-in script that only opens the history files and prints lines. From an AMR Health server it only fetches the Wi-Fi history. No password is stored; nothing on a server is changed.
- **Candidates are files.** A candidate is written to `candidates` and never replaces a source map or an existing candidate. Source maps and recordings are never deleted by the program.
- **Every candidate is checked** and gets a `report.txt` next to it.
- **The AI model sees text results only**, never the map or laser files. API keys are stored encrypted for the Windows user.
- The window talks only to a server on this PC.

## Limits

| Limit | What it means for you |
|---|---|
| The replay tests agreement between map and lasers. It is not the robot's own localiser. | It finds where a map is wrong. It does not predict the exact confidence a robot will show. |
| A replay covers only the route of the recording. | Record through every area you change, in the direction robots drive. |
| A misplaced piece cannot be seen in the map file alone. | **Detect (map file only)** finds lines on paths and broken links. Jumps need a recording. |
| The measured turn has a spread. | Read [[KB-04]]; check the far end of the piece in the trial. |
| Checks cover geometry and properties. | Dock positions need a look at the robot ([[WI-05]] step 7). |
| Adding a feature line by hand is not offered. | Take lines from another map with **Take walls … lines too**, or draw them in RoboShop. |
| Added stations and paths exist only in the map file. | Add them to the fleet scene as well. |
| Tested with maps of one site. | Other map versions may carry fields this version has not seen. They are written back unchanged. |

## Good practice

- Build from the file that is on the robot today.
- One change at a time: one candidate, one trial.
- Keep the old map on the robot under its own name until the new one has run a full shift.
- Save the report and the trial recording with the candidate.
- After a rollout, run **Check maps on all robots**.
