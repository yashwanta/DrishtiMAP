# KB-05 · What is inside a map file

A SEER / RoboShop map is one `.smap` file. These are its parts and how this program treats each.

| Part | What it is | Shown as | Moved by "Move a region" |
|---|---|---|---|
| Wall dots | Every place the scanner saw something solid, on a 5 cm grid | grey dots | yes |
| Reflection points | Dots with strong laser return | cyan dots (Reflectors layer) | yes |
| Reflectors | Reflective markers used in reflector areas | cyan circles | yes |
| Stations | Named points: LM (location mark), AP (action point), CP (charge point), PP (park point) | orange dots with names | yes, with their direction |
| Paths | Lines or curves between two stations, with direction, speed and obstacle settings | green lines | yes, each end follows its station |
| Feature lines | Straight wall segments marked for localisation | pink lines (Feature lines layer) | yes, unless they sit on anchored walls |
| Areas | Reflector areas and other zones | purple outlines (Areas layer) | yes, when their centre is inside |
| Bins | Load positions tied to a station | not drawn | yes, with their station |
| Header | Map name, bounds, resolution | **Map details** | bounds are corrected on every build |

## Station names are what the fleet uses

The fleet manager and tasks refer to stations by name. A candidate must keep every station name. The check list fails if one is missing. A station you add here does not exist for the fleet until it is added to the fleet scene too.

## Path properties

| Property | Meaning |
|---|---|
| `direction` | 0 = the robot drives this path forward, 1 = backward |
| `movestyle` | How the robot moves along it |
| `maxspeed`, `loadMaxSpeed` | Speed limit, empty and loaded |
| `obsStopDist`, `obsDecDist` and the `load…` versions | Distance at which the robot stops or slows for an obstacle |
| `obsExpansion`, `loadObsExpansion` | Extra width checked for obstacles |
| `goodsDir` | Direction of the load on this path |

A path has a start and an end station and can only be driven from start to end. Two-way traffic is two paths.

## The file is kept exactly

The program reads every field, including ones it does not know, and writes them back unchanged and in the same order. An unedited map saved by this program is byte-for-byte the same file. Only what an edit touches differs.

## Same name, different content

The map name is a line in the header. Two files with the same name can differ. The **checksum** (md5) identifies the content: same checksum, same file. The robot reports the checksum of its current map, which is how [[WI-07]] compares robots without downloading anything.
