# WI-09 · Find out what happened to a robot at a past time

**Purpose:** answer "why was AMR-08 off position going to LM279 this morning?" when nobody was recording.

A recording ([[WI-01]]) only covers a drive from the moment you start it. For something that has already happened, the fleet manager keeps a history: one line per second for every robot, with position, confidence, station, planned path and the robot's own warnings and errors. **What happened?** reads that history.

**You need:** this PC on the plant network, and a login on the fleet manager that works with an SSH key (ask IT; a read-only user is enough). No password is typed or stored in this program.

> This only reads. On the fleet manager the program runs one built-in script that opens the history files and prints lines from them. It cannot change or delete anything there.

## A. Set up once per workspace

1. Tools tab, **Past event**, press **History sources …**.
2. **Fleet manager login:** `user@address`, for example `reader@10.0.0.76`.
3. **History folder:** leave empty. Fill it only if your fleet manager keeps the history somewhere else.
4. **AMR Health server** and **Plant name:** optional. With them the report also lists Wi-Fi events. Tick *uses its own certificate* if the server has a self-made certificate.
5. Press **Save**.

If the first run says the login was refused or the server is not known: open a command prompt, run `ssh user@address` once, accept the server's key, and make sure it logs in without asking for a password.

## B. Ask what happened

1. Choose the **Map** the robots use (top of the Tools tab). It is used to name the nearest station and to draw the trip.
2. **Robot:** the name as the fleet manager shows it, for example `AMR-08`.
3. **From** and **to:** start 10 minutes before the event and end 10 minutes after it. Times are the fleet manager's clock. At most 6 hours.
4. Leave **compare with the other robots** ticked. It takes about a minute per day compared.
5. Press **What happened?**

## C. Read the result

| Part | What it tells you |
|---|---|
| First lines | Distance driven, average and lowest confidence, stations reached. |
| **TIMELINE** | Every stop of 20 s or more, position jump, relocalisation, low-confidence stretch and alarm, in time order. Lines starting with `!` are the important ones. |
| **CONNECTION TO THE FLEET MANAGER** | Whether fresh data arrived every second. |
| **OTHER ROBOTS IN THE SAME AREA** | One line per robot for the place where the trouble was: passes, lowest confidence, long stops, errors. |
| **WI-FI IN THE SAME MINUTES** | Access point switches and loss warnings, when an AMR Health server is set up. |
| **IN SHORT** | The findings in plain sentences. |

On the map: the trip is coloured by confidence (green 0.7 or better, yellow 0.5 to 0.7, red below 0.5), each event has a ring with its time, and the dashed box is the area that was compared with the other robots.

## D. What the timeline words mean

| Words | Meaning |
|---|---|
| STOPPED for … | The position did not change for that long. The alarms in the lines around it say why. |
| LOW CONFIDENCE | Below 0.5: the lasers match the map poorly, and the robot leans on its wheels to hold position. |
| heading turned … on the spot while confidence FELL | The robot's idea of its direction turned without it driving. Either it was pushed round, or the position estimate itself turned. |
| position JUMPED | The position moved further in one second than a robot can drive. The robot snapped to a new place on the map. |
| RELOCALISED | Someone, or the fleet manager, told the robot where it is. |
| NO FRESH DATA for … | The history stood still and then showed the robot further on: the fleet manager was not hearing from it. A connection stall, not a position fault. |
| ERROR / warning | The robot's own message, with its code. |

## E. Decide what it is

| The comparison says | Then |
|---|---|
| Most other robots are low in the same area too | The place is weak: what stands there today does not match what was scanned, or there is little for the lasers to see. Record a drive through it ([[WI-01]] C) and run **Detect with Recording** ([[WI-02]]). |
| Only this robot is low there | Look at the robot: scanners (clean, level), wheels, and what stood at that spot at that moment. |
| "Robot is blocked" before the stop | Something was in its way. Check the spot and the time with the floor. |
| "Robot is slipping" | The wheels turned differently from what the lasers saw: a slippery floor, a wheel fault, or the robot pushing against something. |
| NO FRESH DATA, access point switches in bursts | A Wi-Fi matter. It delays tasks and traffic control; it does not move a robot off position. |

## Limits

- The history has **no laser data**. It shows where and when, not which walls failed to match. That needs a recording.
- It is one line per second. Anything shorter is not seen.
- While a robot stands still, unchanged data looks the same as no data, so a connection stall is only seen while it drives.
- Old history is deleted by the fleet manager after some days.
- Robot clocks are often wrong. All times here come from the fleet manager.
